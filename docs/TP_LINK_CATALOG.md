## Pairing rules

- Match the actual operating frequency, channel width and security configuration.
- Pharos standard Wi-Fi peers can use shared same-band modes. MAXtream requires supporting Pharos endpoints; CPE710 does not support it.
- EAP bridge hardware V1 and V2/V3 belong to different pairing generations. Old project entries with no revision stay unverified.
- Flex/modern EAP and Sector/Flex pairings are documented. Disable hub TDMA for EAP clients.
- Modern Sector Bridge hub limit: 32; Flex hub: 8; EAP115/211/215 hub: 4; 2.4 GHz EAP100 hub: 3.
- Beam Bridge mixed-model links remain unverified where documentation does not establish pairing.
- Omada coverage AP mesh is conditional on controller, firmware and uplink-band support. Sharing Omada management is not bridge-kit compatibility.

[Manufacturer pairing guide](https://support.omadanetworks.com/us/document/128124/)
[Pharos MAXtream guide](https://www.tp-link.com/uk/support/faq/694/)

## Modeling limits

Power and receiver sensitivity are still editable planning assumptions, not measured MCS thresholds. Peak gain is per antenna; MIMO gains are not summed. Some hardware revisions and manufacturer pages disagree on beamwidth; those entries identify the uncertainty. EAP725 elevation beamwidth and omni vertical patterns are provisional. Select a band-specific AP preset instead of changing its frequency to another band while retaining the old gain. Six-GHz entries do not model AFC authorization, MLO, failover or availability.

## Project compatibility

The added hardware_revision, wireless_mode and antenna_pattern fields are optional when reading older JSON projects. Catalog selection fills them explicitly. Existing unversioned EAP bridge entries are retained but not silently upgraded to V3.
